# Подключение аналитики — Дом Ульяновск

Документ для владельца сайта и специалиста, который подключает аналитику.

## Текущее состояние

Сайт подготовлен к работе через Google Tag Manager: общий файл `script.js` отправляет события в `window.dataLayer`.

**Счётчики пока не подключены.** В исходниках нет идентификатора контейнера GTM, счётчика Яндекс Метрики или ресурса GA4. До добавления реальных идентификаторов события не передаются в сторонние системы.

Сайт не отправляет на сервер содержимое брифа, имена файлов, фотографии, введённые пользователем данные или номер телефона как параметр события.

## События сайта

| Событие | Когда возникает | Параметры |
|---|---|---|
| `phone_click` | Нажатие на ссылку телефона | `page_path`, `link_location` |
| `contact_cta_click` | Переход к контактам или планировщику | `page_path`, `destination` |
| `mobile_menu_open` | Открытие мобильного меню | — |
| `planner_option_select` | Выбор параметра планировщика | `option_group`, `option_value` |
| `planner_photos_select` | Выбор фотографий для брифа | `photo_count` |
| `planner_photos_clear` | Удаление выбранных фотографий | — |
| `planner_share_complete` | Успешное открытие системного меню отправки или копирование текста | `share_method`, `photo_count` |
| `portfolio_image_open` | Открытие фотографии в галерее | — |
| `faq_open` | Раскрытие вопроса FAQ | — |

Важно: `planner_share_complete` фиксирует открытие системного меню отправки или копирование текста, а не факт получения сообщения компанией.

## Порядок подключения

1. Создать контейнер Google Tag Manager и получить его реальный ID формата `GTM-XXXXXXX`.
2. Добавить официальный код контейнера в `<head>` и сразу после открывающего `<body>` на всех шести HTML-страницах. Использовать только код, выданный самим GTM.
3. В GTM создать триггеры типа **Пользовательское событие** для названий из таблицы выше.
4. Для GA4 создать тег конфигурации с реальным Measurement ID формата `G-XXXXXXXXXX`, затем теги событий GA4 для нужных событий. Передавать только перечисленные выше параметры.
5. Для Яндекс Метрики создать счётчик в кабинете владельца и подключить его официальным кодом или через GTM. При необходимости настроить цели на пользовательские события через поддерживаемый Метрикой механизм.
6. Проверить работу через режим Preview GTM, DebugView GA4 и инструменты проверки Метрики. Тестировать клики, меню, FAQ и планировщик на опубликованном сайте.
7. После проверки убедиться, что события не дублируются и в них не попадают персональные данные.

## Важные замечания

- Не публиковать пароли, секретные ключи и доступы к аккаунтам в репозитории.
- Идентификаторы счётчиков не являются паролями, но добавлять их следует только после создания ресурсов владельцем.
- Перед установкой аналитики необходимо определить применимые требования к уведомлению пользователей, согласию на необязательные cookie и обработке данных. Этот документ не является юридическим заключением.
- Не создавать цели на «отправленную заявку»: на сайте нет серверной формы и подтверждения получения заявки. Сейчас доступны только события действий пользователя.
- После подключения проверить опубликованные страницы, а не только локальную копию.
